# 任务控制台 / Task center

为 DeepSeek Harness 提供**工作区级、跨 Session** 的任务记录器，并把每条真实 Prompt 组织成可点击定位的节点链。

## 核心概念

| 概念 | 说明 |
|---|---|
| 工作区（Workspace） | 任务的隔离级别；对应 DSH 左侧栏里的一个项目。 |
| 任务（Task） | 一个逻辑目标，包含标题、可选短描述和一组 Prompt 节点；不绑定 Session。 |
| Prompt 节点 | 一次真实原生用户输入，记录 `sessionId`、原生 `requestId`、`eventSeq`、`turn`、文本、状态和时间。等待节点还记录 `dependsOn`，在所有依赖节点结束后才提交到原生 Session。 |
| 任务归属（Attribution） | 从任务 Prompt 看板打开一个 Session 后，该会话绑定到这个任务；此后在该会话原生输入框里的每一次真实发送都会成为一个节点。输入框上方显示任务标题、ⓘ 图标和「等待 / 返回 / 取消」按钮。归属按 Session 持久化：刷新页面、Web UI 重连、Host 重启后仍会恢复，并且从左侧栏或其他入口进入该 Session 时也会显示最后一次归属的任务。只有点「取消」才会取消归属。 |
| 原生会话 | 排队、执行、终止都归 Session 自己；普通发送只记录，等待节点在依赖满足后通过原生 `sessionController.prompt` 提交，不绕过原生队列。 |
| 会话标题 | 插件直接使用原生 Session 标题投影；在左侧栏改标题会实时反映到插件，插件 Prompt 看板里的改名也走同一个原生 API，会同步回左侧栏。 |
| 等待节点 | 输入框上方的归属提示条点「等待」打开节点列表，可多选依赖节点；点列表右下角的「提交并等待」后，当前草稿会成为等待节点，所有选中节点结束后自动提交到当前原生 Session。 |
| 快速切换 | 通过浮窗按「最近 + 最常访问」排序列出所有工作区的任务，选中直接进入该任务的 Prompt 看板。 |

Prompt 看板是归属的**切换中心**：从任务 A 进入 Session 后，后续发送属于 A；从任务 B 再进入同一个 Session，归属就替换为 B。每个 Session 各自记住最后一次归属的任务，不同 Session 互不影响。归属不写进原生会话，也不会改变原生消息。无论从左侧栏、快速切换还是其他入口进入 Session，都会显示该 Session 最后一次归属的任务；点提示条上的「取消」才会取消归属并停止记录。

## 使用

1. 点击左侧栏「待办」，进入**总控**：按工作区列出项目。
2. 点击项目，进入**任务看板**：只显示任务、标题和可选短描述；点「新建任务」填写标题和一句描述。
3. 点击任务卡片，进入**Prompt 看板**：Prompt 按 Session 分组，每组一条类似 Git 视图的线性节点链，最新在上。
4. 悬停 / 聚焦节点可查看完整 Prompt；点击普通节点会打开对应的原生 Session，并滚动到该 Prompt 所在轮次。这次进入同样会把 Session 归属到当前任务。等待节点尚未提交到原生会话，点击时显示等待依赖的提示。
5. 在 Prompt 看板点「添加 Prompt」：可以按 Session 标题检索现有会话，也可以选「新建会话」创建一个空白会话；插件打开该 Session 后，在该会话原生输入框里**继续发送的每一条消息**都会成为这个任务的节点。归属会持久保留，刷新或重连后继续有效。
6. 归属期间，输入框上方会显示任务名、标题右侧的 ⓘ 提示图标和「等待」「返回」「取消」按钮：悬停或聚焦 ⓘ 可查看完整说明；点「等待」打开可多选的节点列表，选好后点列表右下角的提交并等待图标；点「返回」打开该任务的 Prompt 看板，但**保留归属**；点「取消」取消归属并停止记录，会话仍然可以继续使用。
7. 从任务看板切换到另一个任务，并再次从它的 Prompt 看板进入同一个 Session，该 Session 的最后归属就改归新任务；之后即使从左侧栏进入也显示新任务。
8. 从**左侧栏直接点击 Session** 不再取消归属：插件会读取该 Session 最后一次归属的任务并显示提示条，后续发送继续记录到该任务。想停止记录时点「取消」。
9. Prompt 看板中每个 Session 分组标题右侧有铅笔按钮：点开可直接修改会话标题，保存后会同步到原生 Session 和左侧栏。左侧栏改名也会立即同步回插件。
10. 任意页面按快速切换快捷键（默认 `Ctrl/Cmd+Shift+K`；Web Linux 为 `Ctrl+Shift+,`，可在 DSH 快捷键设置中修改），或点页面上的「快速切换」按钮，打开任务浮窗；输入可搜索，↑↓ 选择、Enter 打开、Esc 关闭。任务按最近活动和访问次数综合排序，选中后直接进入该任务的 Prompt 看板。
11. 任务标题、描述可随时编辑。Prompt 节点是历史记录，像 git log 一样不提供单节点删除；只能在任务级别删除整个任务（不会删除原生会话消息）。

## 等待节点（多依赖）

归属提示条上的「等待」按钮打开**跨任务节点列表**。列表显示每个节点的 Prompt 文本、所属任务/项目、Session 标题、状态和时间，可以搜索，也可以多选。

- 选中一个或多个节点；列表右下角的圆形箭头（箭头旁带小时钟，区别于原生发送按钮）是**提交并等待**。
- 点击后插件读取当前原生输入框里的草稿，创建一个 `waiting` 节点，然后清空输入框。普通发送仍然是普通发送；只有点这个按钮才会等待依赖。
- **所有**选中的依赖 Prompt 都到达 `done` / `failed` / `cancelled`（即结束），**并且**它们所在 Session 的 Agent 已经 `idle`、`next-turn` 和 `next-step` 两个原生队列都为空之后，Host 才通过原生 `sessionController.prompt` 把等待节点提交到目标 Session。目标 Session 原有的排队/执行规则不变；如果目标忙碌，等待节点会排在原生队列里。
- 等待节点出现在目标任务的 Prompt 看板中，状态为「等待依赖」，并显示「等待 N 个节点」。它的草稿在提交时已由 Host 持久化，浏览器关闭后仍会继续等待和执行。
- 依赖结束早于提交时，提交后只要依赖 Session 已经排空就立即发送；依赖在提交后才结束时，`turn/end` 只更新状态，真正的唤醒要等依赖 Session 的队列/插队批次处理完。依赖在输入期间结束不会发送任何东西，因为此时还没有创建等待节点。
- 如果依赖是被从原生队列取消的，`agent/inbox/discarded` 会把依赖标为已取消，等待节点按「结束」语义继续；如果依赖节点因所在任务被删除而不存在，等待节点会失败并显示原因，不会永久挂起。
- 依赖判断是事件驱动的：`turn/end`、`agent/status`（idle）、`agent/inbox/spliced`、`agent/inbox/discarded`、提交、任务删除和 Host 启动重建都会检查；**没有定时轮询**。客户端只在打开节点列表时读取一次候选节点，草稿只在点「提交并等待」时读取一次。
- 提交使用客户端 `commitId` 和等待节点的 `requestId` 做两层幂等：网络重试不会创建第二个等待节点，Host 崩溃后重启也会用同一个 `requestId` 向原生 admission 重试。
- 列表选择在关闭/重新打开同一个 Session 时会保留，因此可以先选依赖、再输入、再回来提交；切换目标任务/会话才清空选择。
- v1 只接受纯文本草稿。带附件、文件/链接引用或命令的草稿会给出提示，不会静默丢失结构。

### 队列 / 插队屏障

原生 Session 有两种把输入放进队列的方式，行为不同：

- **按序排队（`next-turn`）**：当前轮 `turn/end` 后，下一条排队 Prompt 会开始新的 `turn/start`。因此不能把“依赖 Prompt 自己的 `turn/end`”当作整个 Session 完成；否则等待方会和下一条排队 Prompt 同时运行。
- **插队（`next-step`）**：插队消息在当前轮的下一个 step 处理，通常依赖 Prompt 的 `turn/end` 已经覆盖这批插队；但轮末/轮后新插入的 `next-step` 仍可能落在 `turn/end` 之后，所以也需要额外屏障。

实现上，等待节点就绪需要同时满足：

1. 依赖 Prompt 状态为 `done` / `failed` / `cancelled`；
2. 依赖 Prompt 所在 Session 的 Agent 状态为 `idle`；
3. 该 Agent 的 `inbox.next-turn` 和 `inbox.next-step` 都为空。

Host 通过 `ctx.agents.get(sessionId)` 读取实时 Agent 状态和 inbox，并在 `turn/end`、`agent/status` 变为 `idle`、inbox splice/discard、提交、任务删除和启动重建时重新检查。多个依赖是 AND：每个依赖 Prompt 都结束，且每个依赖 Session 都排空，才会提交等待节点。这相当于把依赖 Session 当成一把锁：锁持有期间（还有 running 轮或 pending 队列）等待方不启动；锁释放后等待方一起被唤醒。

锁释放后新插入到依赖 Session 的 Prompt 属于下一批工作，可能和等待方并行；这是锁语义而不是丢事件。检查与原生 admission 之间没有定时器，也没有轮询。

## 会话标题同步

原生 Session API 支持改名：左侧栏改名本身调用 `sessions.using(sessionId, …).binding.session.rename(title)`；成功后会写入原生 `title` 投影，Session 列表和侧栏一起更新。本插件用同一路径改名，并订阅 `sessions.list`，因此：

- 左侧栏改名 → 插件 Prompt 看板的 Session 分组标题、选择器标题立即更新；
- 插件内改名 → 原生 Session 标题和左侧栏更新；
- 改名失败（权限、会话已删除等）会在 Prompt 看板顶部显示错误，不会只改插件本地显示。

## 快速切换任务

- 浮窗数据来自 Host 的 `GET /tasks`（当前所有工作区的任务摘要），不读取 Prompt 正文。浮窗会先展示上一次成功读取的缓存；工作区注册表短暂刷新导致读取失败时自动重试 2 次，仍失败也只会在列表上方提示，不会用错误页替换已有任务。
- 排序分数 = `(访问次数 + 1) / (1 + 最近活动距今天数)`；最近活动取任务的 `lastVisitedAt`、`updatedAt`、`createdAt` 最大值。访问次数和最近访问时间随任务保存在 Host 数据文件里，重启或换浏览器都保持；访问任务本身不会改动 `updatedAt`。
- 选择任务后设置目标视图并选中「待办」面板，因此从任何页面都能直接落到指定任务的 Prompt 看板。
- 快捷键是 DSH 可编辑快捷命令（id：`session-todo.quick-switch`），默认值如上；Web Linux 只允许浏览器安全的 `Comma` 组合，可在设置里重绑。

## 定位机制与限制

DSH 目前没有公开的「打开 Session 并定位到某一轮」API。本插件使用原生 Chat 的内部锚点完成定位：

1. 调用 `uiWorkspace.openSession(sessionId)` 打开会话；
2. 通过 `ctx.sessions.binding(sessionId).session.loadOlder()` 分批把历史翻到目标轮次（而不是一次 `loadThrough` 发布全部页面，避免一个长主线程任务；实测最坏长任务从约 2.1 秒降到约 0.46 秒）；
3. 查找原生 Chat 行上的 `data-chat-turn` 锚点，暂停跟随（合成一次 `wheel` 意图），滚动到该行并短暂高亮。

这意味着定位依赖 DSH 客户端内部结构（`data-chat-turn`、`data-conversation-session`、`data-conversation-scroll`、`data-rightbar-col`、`data-sidebar-chat`）。DSH 升级后如果这些锚点变化，定位会失效，但任务数据、看板和原生会话本身不受影响。定位结果提示只属于发起定位的那个任务：切换任务、返回看板、或提示超过 10 分钟会自动清除，不会再出现在新建的无 Prompt 任务里。正在执行的 Prompt 定位不到稳定行时只滚动到会话最新位置，不显示失败提示。

## 外观一致性

- 插件内所有带边框/背景的「框」（卡片、对话框、搜索框、输入框、按钮、提示条等）统一使用原生 composer 的 `var(--dsw-radius-panel)`（当前为 28px）圆角；只有圆点和状态圆点保留 50%。
- 快速切换卡片的搜索框高度为 44px，和卡片一样使用 28px 圆角；搜索框内文字为 13.5px。
- 归属提示条保留圆点、任务标题、ⓘ 图标和「等待/返回/取消」，说明文字放在 ⓘ 的悬浮提示里，避免挤压原生输入框上方的空间。等待节点列表复用快速切换卡片的原生圆角和层次。

## 状态语义

- 归属是会话级的：只要该 Session 有持久归属，每一次由人发出的 `agent/inbox/spliced` 用户消息都会成为一个节点；同一原生请求不会重复创建节点。
- 归属持久化在 `todos.json` 的 `sessionTasks` 中：Host 重启、Web UI 重连、页面刷新都不会丢失；从任何入口进入 Session 都会显示最后一次归属的任务。
- 会话页每 2 秒读取一次归属，用于更新标题和任务名，但读取本身不会改变归属；只有「取消」、删除任务、或把同一 Session 归属到另一个任务才会改变它。
- 同一标签页刷新会从 `sessionStorage` 立即恢复本地镜像；新标签页/新页面则从 Host 的持久记录读取。两者都不需要重新从看板进入。
- 升级到持久归属后，首次启动会从已有 Prompt 历史为缺失的 Session 补一次「最后归属」；之后 `attributionVersion` 会阻止取消过的归属在重启时被重新补回。
- 归属消息只记录文本；图片/文件以占位文本记录。
- 普通新节点初始为「排队中」；原生 `user/message` 到达后变为「执行中」，`turn/end` 后按原因变为「完成 / 失败 / 已取消」。等待节点先处于「等待依赖」，所有依赖 Prompt 结束且依赖 Session 的 queued/steer 批次排空后由 Host 提交，随后按原生队列变为排队中/执行中/完成等。
- 等待节点的依赖是**全部结束**（AND），不是任意一个结束；结束包括完成、失败和已取消。依赖 Session 还必须 `idle` 且 `next-turn` / `next-step` 都为空，队列/插队批次不会在等待方启动后继续跑。实现不使用轮询，依赖状态来自持久数据和 Agent 事件。
- Prompt 节点不提供单节点删除；历史记录不可变，只有任务级别删除。

## 数据

- 文件：`~/.dsh/session-todo/todos.json`（JSON，原子写入，0600）。
- 当前只支持 v3 数据。旧 v1/v2 文件不会被自动迁移，而是改名保留；如果确实需要旧数据，请先手动转换。
- v3 新增可选的 `sessionTasks`（每个 Session 的最后任务）和 `attributionVersion`；旧 v3 文件缺少这两个字段时会自动补一次迁移，不需要手动改文件。等待节点新增可选的 `dependsOn` / `commitId`；旧 Prompt 没有它们时按无依赖处理，不影响读取。
- 任务描述上限 600 字符；标题 200；Prompt 20000；每个任务最多 500 条 Prompt；每个工作区最多 200 个任务；最多保留 1000 条 Session 归属。等待节点额外保存 `dependsOn`（最多 20 个节点）和客户端 `commitId`；旧数据缺少这些字段时按无依赖处理。
- 每个任务还带有 `lastVisitedAt` / `visitCount` 两个快速切换排序字段；旧数据没有它们时按无访问处理，不需要迁移。
- 数据不进入会话事件日志，也不进入模型上下文。

## 开发

| 文件 | 职责 |
|---|---|
| `index.js` | Host 装配：store、tracker、routes、Session 事件与启动重建。 |
| `store.js` | v3 数据模型、校验、原子持久化。 |
| `prompt-tracker.js` | 会话级持久归属、节点落成、状态迁移、等待节点依赖判断与原生提交、取消/删除传播、重启后按日志重建。 |
| `routes.js` | 本机 HTTP 桥：项目 / 任务列表 / 任务 / Prompt / 等待节点候选 / 归属（arm、release）。`releaseAll` 保留为兼容空操作，不再清除持久归属。 |
| `client.js` | 总控、任务看板、Prompt 节点链、会话标题同步/改名、快速切换浮窗、等待节点多选列表、悬停预览、原生定位、归属提示条。 |

修改 `client.js` 后刷新页面或等待客户端 HMR；Host 改动需要重载插件或重启 `dsh web`。等待节点会调用 Host 的 `sessionController`，并通过 `agents` 读取依赖 Session 的 Agent 状态和 inbox；Host 侧需要这两个服务可用。
